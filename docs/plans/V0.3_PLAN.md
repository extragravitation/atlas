2026-11-18. **Basis: D-112.** v0.3 is the next release. It is still preliminary and not peer reviewed. It is built so that the working astronomers it is shown to take it seriously. ## What a respected v0.3 needs, in order of work

### 1. Provenance complete for every shipped source (largest item; starts first)

- **Now:** `sources.json` across the six v2 packages has a citation in 0 of 226 entries and a licence in 36 (the strong lenses and X-COP). This is the main reason the audit did not pass (#186: 250 rows). The text exists, but outside the package.
- **Work:**
  1. a minimal **data standard 3.0.0**: required `citation` and `licence` on every `sources.json` entry, and a locator (table, page or column) for every value the package reads;
  2. frozen before any package is re-issued (D-107 rule 4, D-109);
  3. then each package is re-issued as v3 with `convert.py` unchanged.
- **Test, frozen before the first re-issue:**
  - every v3 table equals v2 bit for bit;
  - every entry has a citation, a licence and a locator;
  - every URL in the locators resolves, or is recorded as unreachable with its hash.
- **Not in v0.3:** the other 3.0.0 items that need new readings or a new taxonomy version. They come in the full re-issue for v1.0.

### 2. Front page leads with the cross-scale view

- The opening screen is the g_obs against g_bar view, from star clusters to galaxy clusters, with motions and light-bending kept apart, and each point a click from its source.
- The audit result stays where it is (Reproduction and About; it is not on the front page), unchanged in substance.
- **Check:** read in both layers (technical and plain), on desktop and phone, with screenshots.

### 3. Well-known test systems and the scope (completeness plan 1.3 and 1.4, lean)

- **1.3, a new section on Coverage:**
  - **Systems:** the 41 used as tests by two or more of the five reviews (`docs/sources/checklist-reviews.md` §2), plus CK-01's starting list as corrected there.
  - **Each row:** status (in / candidate with its cell / excluded with the rule / gap with the reason), who uses it as a test and for what, and its disputed inputs.
  - **Form:** a ruled data file rendered by the build, like the rest of Coverage.
- **1.4, scope statement for both sides:** what the Atlas does not carry and why, each item with its review source. It needs JvH's ruling on the boundary question in `checklist-reviews.md` §4.

### 4. The D-038 effect stated (completeness plan 1.5, first case only)

On Coverage: which named test systems the D-038 dispersion rules remove (Carina, Crater II), and whose case those systems are usually cited for. No rule changes in v0.3; any change goes through the deviations register later.
